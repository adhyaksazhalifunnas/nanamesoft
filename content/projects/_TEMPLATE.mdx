The body below is MDX. The frontmatter above already supplies the Decision
Table, the metrics table, the constraints list, the limitations, and the
repository evidence block — those are rendered from structured data so they look
identical on every case study and cannot be forgotten.

Use this body for the two things that cannot be structured: the **Context**
narrative and the **Implementation** walk-through.

## Context

Two or three paragraphs. What existed before, who it affected, and what was
actually going wrong. Concrete beats comprehensive.

## Implementation

How the interesting part actually works. One well-chosen code excerpt of 15–30
lines, with commentary on _why it looks like that_. Do not paste the whole
module — that is what the repository is for.

```ts
// A short, real excerpt. Shiki highlights this at build time,
// so no syntax-highlighting JavaScript reaches the browser.
export function reconcile(current: Row, pending: Write[]): Row {
  return pending.reduce(merge, current);
}
```

Then one paragraph on what that code is doing that is not obvious from reading
it — the failure mode it handles, or the thing you tried first that did not work.
